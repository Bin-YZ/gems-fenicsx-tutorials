## 一、为什么和原 notebook 不逐位相同

### 1. ✅ GEMS 的解对第 15 位有效数字敏感

- 单节点测试（calcite 体系，热启动）：b 向量的 H 改动 1e-15（相对），物种量变化 4e-7。
- 模板和原 notebook 送进 GEMS 的 b 向量只差 2e-16（求和顺序、矩阵组装顺序不同），结果就在 GEMS 收敛容差内漂动：
  calcite 白云石 7e-4、HAYEKIT 8e-8、OPC 矿物 ≤ 4e-4。
- 和 OGS 参考比，误差表和原 notebook 一样，说明这不是模板的问题。

### 2. ✅ ConcentrationToMass 的求和顺序照 OGS

- OGS（2015、2017 版都是）：`soluteB = c·V_f`，取绝对值，`soluteB += 溶剂水的 H、O`，最后 `b = b_fix + soluteB`。
  模板照这个顺序（`gems_ogs.py concentration_to_mass`）。
- 试过先加 b_fix 再加水：calcite 结果不变，comedy2d 碰巧少一个失败节点。按第 1 条，这种差别没有物理意义，所以按 OGS 源码的顺序写死。

## 二、OGS 不同版本的规则 —— 写成了构造函数的选项

| 选项 | 含义 | 用到的算例 |
|---|---|---|
| `hydrology='full'` | `$FLAG_COUPLING_HYDROLOGY 1`：整个水相缩放到孔隙体积 | calcite、comedy2d、ConcreteCrack |
| `hydrology='hayekit'` | `$FLAG_HAYEKIT`：只缩放溶剂水 | HAYEKIT |
| `hydrology='none'` | `$FLAG_COUPLING_HYDROLOGY 0`：c = 水相量 / 水相体积，b = b_fix + c·φ | OPC |
| `limits='loose' / 'strict'` | `$LOOSE_KINETICS`：动力学窗口的另一端取当前量 / 钉在目标值 | comedy2d 两种都算 |
| `seed_omega`、`seed_needs_rate` | 成核判据：2013–2015 版 Ω ≥ 1.0001；2017 版 Ω ≥ 1.1 且本步速率 ≠ 0 | comedy2d 用 2017 版 |
| `check_lower_limits` | 2017 版 CheckConstraints：下限所需元素量不超过节点总量 | comedy2d |
| `substep_kinetics` | 2017 版 MaxDtKinetics 子步；中间子步失败继续，最后一步失败才算节点失败 | comedy2d |
| `retry_widen` | 2015 版：失败后 dll×0.999999、dul×1.000001 再算一次 | 没有算例用 |
| `warm_start` | 每节点一个 GEMS、热启动 | calcite（原 notebook 这样做） |

- ⚠️ comedy2d 的参考解是 2017 年的代码（提交 8e2cf24），所以子步失败的处理照 2017 版；
  一开始照 2015 版写成“后面子步失败就保留前一个好的子步”，后来查 2017 版源码改了过来。

## 三、算例里遇到的问题

### 3. ⚠️ comedy2d：前沿节点上 GEMS 偶尔因舍入返回 ERR（`retry_perturb`，不是 OGS 的规则）

- 节点 1311（x = 9 cm，y = 13 cm，反应前沿）在第 2 步返回状态 4（ERR_GEM_AIA）。照 OGS 规则这个节点整步保留旧值，
  局部 Ca 和参考差 10 %，多余水源项也变了，水头差 6e-7。
- 同样的输入把 b 改动 1e-12（相对）就收敛了。原 notebook 在别的步、别的节点上也有 1–2 个这种失败，位置随舍入变化。
- 处理：加了 `retry_perturb=1e-12` 选项，失败时用 b × (1 + 1e-12) 再算一次。comedy2d 用了它之后没有失败节点，
  Ca 和参考差 1.4e-4（同原 notebook），水头 1e-9、速度 7e-6 / 1e-5（原 notebook 7e-8 / 1.2e-4 / 5.5e-4）。
- OGS 内置的是 2017 年的 GEMS3K，xgems 是新版，失败的节点本来就不会一样；这个选项只是让偶发失败不把节点冻住一整步。

### 4. ✅ GEMS 物种名的编码

- ConcreteCrack 的 `cement_bc-dch.dat` 里 `strätlingite` 是 Latin-1，xgems 的 `speciesName()` 会抛 UTF-8 错误。
- 模板统一从 DCH 文件按 Latin-1 读元素、物种、相名（`<ICNL> <DCNL> <PHNL>`），并检查个数和 xgems 一致。

### 5. ✅ 四边形顶点顺序和单元映射

- OGS 四边形是逆时针顺序，dolfinx 要求张量积顺序；用 `dolfinx.cpp.io.perm_vtk` 换序后 `create_mesh`。
- 单元数据按 OGS 单元编号存，`OGSMesh.cell_of_dof0` 把它放到 DG0 自由度上；检查过 comedy2d 和 calcite 每个 dolfinx 单元的节点集合和对应 OGS 单元一致。

### 6. ❓ ConcreteCrack：水流矩阵病态，水头只能到 1e-5 m

- 裂缝 K = 0.41 m/s，混凝土 5e-11 m/s，差 10 个数量级。同一个矩阵（逐元素相同，差 1e-23），按 OGS 节点顺序和按 dolfinx 自由度顺序直接求解，
  水头差 1.5e-5 m。所以模板和原 notebook 的水头差 2.6e-2 m（这里本来还叠加了 GEMS 多余水的噪声）。
- 影响：表层 Cl / N / Na 的极小尾巴（边界值的 1e-4 以下）。主结果 Cl 和参考差 2e-4（原 notebook 8e-5）；Ca、Si 等 ≤ 1.3e-3，和原来一样。
- ⚠️ 原记录第 7 条说 “照 OGS 的 FCT 符号更接近参考”（8e-5 vs 1.6e-4）。用模板重算，教科书符号反而略好（1.6e-4 vs 2.0e-4）。
  两种写法的差别比这个水头舍入误差引起的差别还小，**那条结论不可靠**，应以 “分辨不出” 为准。

### 7. ⚠️ HAYEKIT 的边界节点

- `ab1d.gem` 写了 `$FLAG_CALCULATE_BOUNDARY_NODE 1`，但原 notebook 两端不算化学（和 OGS 的结果对到 2e-5），模板保持一样。

## 四、模板没有包括的

- Richards 非饱和流（TransLay2d）、温度、气相输运、Nernst–Planck、并行。TransLay2d 第 1、2 步的 Richards 代码在
  `TransLay2d_Richards_FEniCSx` 里，要加进模板可以照 `flow.Darcy` 写一个 `Richards` 类（Picard + 集中储水项），
  再给 `OGSGEMS` 加 `hydrology='richards'`（缩放到 φS，见那个文件夹的记录）。
- 动力学只支持单物种相（固溶体的 ω 重新分配端元是 TransLay2d 第 3 步才用到的）。
